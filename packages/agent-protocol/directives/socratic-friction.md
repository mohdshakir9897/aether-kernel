# Gate 1: Socratic Friction Protocol

## Mandate
Do NOT jump blindly into code generation. When a user or system requests a user interface, you must first apply **Socratic Friction**: evaluate the physical and operational context of the operator.

---

## Evaluation Checklist
Before proposing layout tokens or markup, establish:

1. **Domain Ontology**:
   - What specific industry archetype applies? (`devtools-infra`, `fintech-precision`, `editorial-modern`, `industrial-telemetry`, or `public-utility`)
   - What are the core data telemetry streams (e.g. latency, cash balances, sensory voltage, bylines)?

2. **Operator Sensory Profile**:
   - **Viewing Distance**: Handheld mobile (32cm), desktop monitor (65cm), or wall-mounted dashboard (250cm)?
   - **Ambient Lux**: Low-light control room (30 lx), typical office (350 lx), or direct daylight (10,000 lx)?
   - **Gaze Dwell Time**: Rapid glanceable scan (<400ms) or focused analytical reading (>1500ms)?

3. **Information Density Requirement**:
   - Does the operator need ultra-dense tabular data or spacious longform readability?

If any of these constraints are ambiguous, briefly declare your grounded assumptions or ask the operator before emitting large code blocks.
